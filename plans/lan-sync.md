# SmartClip: LAN-синхронизация между устройствами (дизайн, без кода)

**Цель:** запись, добавленная на одном устройстве, появляется на остальных.
Синхронизируется полный стейт, включая избранное. Без серверов — только прямая
связь в одной локальной сети.

Статус: дизайн/план. Код не написан.

---

## 1) Обнаружение

- mDNS/DNS-SD (Avahi на Linux, Bonjour на macOS), сервис `_smartclip._tcp.local`.
- TXT-записи: `deviceId`, имя, версия протокола, роль, отпечаток публичного ключа.
- Фолбэк: ручной ввод IP + UDP-broadcast announce (на случай сетей, где mDNS
  зарезан: гостевые сети, VLAN).

## 2) Транспорт

- Прямой TCP между устройствами в LAN; порт эфемерный, публикуется в mDNS.
- Сверху — TLS 1.3 с самоподписанными сертами, закреплёнными по публичному ключу
  (pin). Проще, чем QUIC, и достаточно.
- Соединение инициирует **ведомый**, мастер только отвечает — упрощает firewall/NAT
  внутри сети.

## 3) Сопряжение и аутентификация

- Доверенное сопряжение при первом контакте (модель TOFU): обмен публичными
  ключами Curve25519, обе стороны показывают один и тот же короткий код/QR,
  пользователь подтверждает.
- Далее — белый список ключей устройств и взаимная аутентификация.
- Никаких паролей в сети.

## 4) Шифрование

- **Канал:** TLS 1.3 / Noise (эфемерные ключи → forward secrecy); плейнтекст ходит
  ТОЛЬКО внутри туннеля.
- **Хранилище:** уже есть AES-256-GCM, ключ в Keychain / Secret Service — то, что
  лежит на дисках, остаётся зашифрованным как сейчас.
- Anti-replay, rate-limit, bind только на LAN-интерфейс.

## 5) Что гоняем (модель данных)

Модель записи переводим с «ключ = текст» на стабильный `id` (UUID) + метаданные:

```
{
  id,                       // UUID, стабильный
  text,
  usageCount,
  addedAt,
  favoriteColorIndex,
  maskInMenu,
  hlc,                      // Hybrid Logical Clock
  originDevice,
  deleted                   // tombstone
}
```

- **Полный стейт:** при первом контакте или рассинхроне — обмен всем списком.
- **Дельты:** дальше — только изменения с известного «водяного знака»
  (state vector по устройствам).
- **Удаления** — через tombstones, иначе удалённое возвращалось бы обратно.

> Лимит ~32 элемента → payload крошечный. Полный стейт можно гонять хоть каждый
> раз; дельты — оптимизация на будущее.

## 6) Конфликты

- Порядок без общих часов — Hybrid Logical Clock (HLC).
- Скалярные поля (`text`, `favoriteColorIndex`, `maskInMenu`) — Last-Writer-Wins
  по HLC; `usageCount` — суммировать (counter) либо брать max.
- При точном равенстве выигрывает мастер.

## 7) Роли: мастер и ведомые

Топология «звезда», НЕ полный mesh — проще и предсказуемее:

- **Мастер** (ведущее, приоритетное): авторитетный стейт; при равных метках его
  версия побеждает; хранит полный журнал и водяные знаки по каждому ведомому.
- **Ведомые:** шлют свои изменения мастеру, получают дельты; сами между собой
  напрямую не синкаются.
- Мастер один и выбирается пользователем в настройках. Если мастер offline —
  ведомые копят локальные дельты и догоняют при возврате.
- Двух мастеров не допускаем (иначе классический split-brain).

## 8) Сессия синка

```
Discover
  → handshake + проверка ключа
  → Hello { deviceId, роль, state vector }
  → ведомый push локальных изменений / мастер отдаёт diff
  → apply, ack, сохранить watermark
  → keepalive
```

Триггеры: новое событие (новый клип/избранное) — push сразу; плюс периодическая
сверка и полный reconcile при старте или смене сети.

## 9) Ограничения и риски

- mDNS не проходит между VLAN / гостевой сетью; на macOS нужен Local Network
  permission; возможны фаерволы. Ограничение по подсети.
- Несколько мастеров = конфликт (решаем выбором одного).
- Часы — покрывает HLC.

## 10) Этапы

1. Ввести `id` + HLC в модель и в хранилище (миграция).
2. Сопряжение + TLS-канал (тест на loopback).
3. mDNS-обнаружение.
4. Полный стейт master/slave.
5. Дельты + push.
6. Tombstones и разрешение конфликтов.
7. UI: список устройств, выбор роли, индикатор синка.
8. Тесты: две копии на одной машине, конфликт LWW, offline-догон.

**Короткий вывод:** реально и без серверов. Архитектура «звезда с одним мастером»
+ mDNS + TLS с pinning + HLC/LWW. Шифрование канала — TLS/Noise, хранилище уже
AES-GCM. Главная работа — не транспорт, а аккуратная модель данных (id + время +
tombstones) и сопряжение устройств.

## Привязка к текущему коду (заметки по реализации)

Файлы проекта: `HistoryManager.{h,cpp}`, `SmartClipApp.{h,cpp}`, `Crypto.{h,cpp}`,
`SettingsManager.{h,cpp}`, сборка — CMake + `build-linux/`.

**Модель.** Сейчас `HistoryManager::HistoryItem` = `{ text, usageCount, addedAtMs,
favoriteColorIndex, maskInMenu }`, а `favoriteItemColors` в `SmartClipApp` — это
`QHash<QString,int>` (ключ = сам текст!). Для синка нужен стабильный `id`:
- добавить в `HistoryItem` поля `id` (QUuid), `hlc`, `originDevice`, `deleted`;
- ключи `favoriteItemColors` и `toggleFavorite`/`isFavorite`/`maskInMenu` тоже
  завязаны на текст → переводить на `id` (иначе дубликаты текста и правки ломают
  адресацию);
- `favoriteColorIndex` уже есть в `HistoryItem` — синкается как скаляр (LWW).

**Хранилище.** Формат `~/.smartclip/history.yml` уже версионный (`version: 2`,
поле `text_b64: v2:<base64>`). Добавление полей = `version: 3` с миграцией
v1→v2→v3 (v1 — открытый, v2 — AES-GCM, v3 — +id/hlc/tombstone). Ключ шифрования
уже выдаётся через `Crypto::loadOrCreateKey("SmartClip","history-aes-key")`.

**Важно для синка:** ключ AES-256-GCM **свой на каждом устройстве** (в keyring),
поэтому «гонять» по сети нужно PLAINTEXT внутри TLS-туннеля, а не сохранённый
шифртекст. То есть в п.4 «хранилище остаётся зашифрованным как сейчас» —
верно для диска, но для wire-формата используем плейнтекст под TLS/Noise.

**Настройки.** Роль (мастер/ведомый), `deviceId`, белый список ключей — в
`SettingsManager` (settings.yml). UI выбора роли — рядом с существующими
пунктами меню трея (`favoriteModeAction`, `revealModeAction`).

**Платформенные детали.** Стек Qt6/Widgets: TCP — `QTcpSocket`, TLS — `QSslSocket`
(pinning через `QSslCertificate`/`verify()`), шифрование канала можно и на
`QCryptographicHash`/`QRandomGenerator`; для mDNS на Qt6 — `QNetworkInformation`
не покрывает DNS-SD, нужен либо Avahi/Bonjour через DBus (`QDBusInterface`),
либо сторонняя либа.
